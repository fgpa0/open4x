# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Open4X, a Civ-like 4X game in Rust + Bevy 0.20, open source under GPL-3.0-or-later. Design pillars: fast AI turns, unit and city automation (standing orders, governors, auto-research) that the player can always override, moddable rules in `data/*.ron`, and visuals that look like a real game. All art is procedural, made in code (Rust, or Python scripts run in Blender for models); there are no third-party assets except OFL fonts.

**Start here:** `ROADMAP.md` (local only, not in git) has the current status, what to build next and the design decisions already made. Keep it up to date when finishing work.

## Commands

`cargo` lives in `~/.cargo/bin` (add it to `PATH` if needed). Use `--release` when running the client; debug builds are slow.

```sh
cargo run --release -p client                     # play
cargo test --workspace --release                  # all tests
cargo test -p sim --release research::            # tests in one module (or a single test name)
cargo clippy --release -p client -p sim
cargo run --release -p headless -- 200 3 7 150    # AI-only game: turns players seed [turn limit] (timing, eliminations, winner, per-player summary with the turn each era was reached); FOURX_MAP=pangaea etc. picks the map type
FOURX_AI_LOG=25 cargo run --release -p headless -- 200 6 1   # also print each AI's strategy every 25 turns
FOURX_ARMY_LOG=1 cargo run --release -p headless -- 250 6 3  # also list every military unit's order and every city's defence at the end
FOURX_WAR_LOG=1 cargo run --release -p headless -- 250 6 1  # also print wars, peace, captures, every attack on a city, target switches (counted at the end), and each warring AI's target and the units sent to take cities every 5 turns
cargo run -p sim --example ascii_map|map_stats|city_growth <seed>   # map generation and balance checks (ascii_map <seed> <map type> [small|standard|large] also lists landmasses)
blender -b --factory-startup -P art/build.py -- [model ...] [--no-preview]   # rebuild Blender models (all without names); previews in target/art
cargo run --release -p sim --example start_bias [maps] [players]   # how well starts match civs' start biases
```

### Client dev environment variables

They're used for verification, because the game is mostly checked with screenshots. Normally the client opens on the main menu; with `FOURX_SCREENSHOT` or `FOURX_PLAY` it skips the front end and starts a 4-player game (seed `FOURX_SEED`, default 7) straight away.

- `FOURX_SCREENSHOT=out.png[,x,z,dist | ,far[,dist] | ,loading]`: waits about 8 s after loading, saves a screenshot, logs FPS and GPU pass times, then exits. On a front-end screen (`FOURX_MENU=main|civs|setup`) it waits 4 s instead.
- `FOURX_SHOT_AT=s`: takes the in-game screenshot `s` seconds after loading instead of 8 (e.g. `1.5` during the intro flight).
- `FOURX_STARTS=slot:tile,...`: on the setup screen, places those player slots' starts (0 is you) on the first map preview.
- `FOURX_PLAY=1`: skips the front end.
- `FOURX_LOAD=path.sav`: with `FOURX_SCREENSHOT` or `FOURX_PLAY`, opens that save instead of a new game (e.g. a late game from `~/.local/share/fourx/saves` for profiling). Screenshot runs keep full speed without window focus; to measure above the monitor's refresh rate on Wayland, run with `env -u WAYLAND_DISPLAY` (XWayland).
- `FOURX_CIV=netherlands`: the player's civ (by id from `civs.ron`), for direct starts and preselected in the front end.
- `FOURX_SIZE=small|standard|large`: map size for direct starts and the front end's setup.
- `FOURX_MAP=continents|pangaea|archipelago|fractal|inland_sea|terra|earth`: map type for direct starts and the front end's setup (default Continents; `FOURX_SIZE` likewise) and for `headless` (default Fractal).
- `FOURX_TRUE_STARTS=0|1`: True Start Locations on Earth; on by default in the client (`0` turns it off), off by default in `headless` (`1` turns it on).
- `FOURX_CLICKS=x,y,t;x,y,t...`: left-clicks at window position (x, y) `t` seconds after startup, to click through the front end in screenshot runs. `x,y,t,down`, `x,y,t,move` and `x,y,t,up` press, move and release separately, for drags. With a trailing `;game` the screenshot is taken in game after loading. Example, main menu to game: `FOURX_MENU=main FOURX_CLICKS="297,476,2.5;200,199,3.5;1420,861,4.5;1420,861,5.5;game"`.
- `FOURX_CURSOR=x,y`: a virtual mouse cursor, so tooltips and hover cards show up in screenshots. `FOURX_CURSOR=duel` points it at the first `FOURX_DUEL` enemy.
- `FOURX_DUEL=1`: puts enemy units next to your warrior (one fortified, one wounded, one civilian), declares war on their civ and selects the warrior, for testing combat. `FOURX_DUEL=peace` stays at peace, to test the declare-war prompt.
- `FOURX_RES=WxH`: window size.
- `FOURX_SEED`: map seed.
- `FOURX_TURNS=n`: auto-plays n turns first. Your units explore and the settler founds a city.
- `FOURX_LOG=1`: opens the notification log; with `FOURX_TURNS` the auto-played turns' news goes into it.
- `FOURX_OPEN_CITY=1`: opens your first city's panel. With `FOURX_BUY_TILES=1` it also shows the tiles it could buy, with prices.
- `FOURX_GOLD=n`: sets your gold (for testing purchases).
- `FOURX_TREE=1`: opens the tech tree.
- `FOURX_MENU=pause|settings`: opens that menu in game. `main`, `civs` or `setup` opens that front-end screen instead; `maptypes` opens game setup with the map type picker open.
- `FOURX_NAVY=1|fleet`: puts your galley, quadrireme, caravel, frigate (with an Admiral on its tile with a level to spend; `fleet` selects the frigate), a galleon, a destroyer, a battleship, a second Admiral and an embarked scout on the water near your start, with an enemy galley, gives you every tech and logs the scout's and the lone Admiral's world positions (for a close-up `FOURX_SCREENSHOT=out.png,x,z,9`).
- `FOURX_ARMY=1|enemy`: gives you every tech and puts five units (of every rank, a General with a trait to choose on the warrior's tile) on open ground near your start, with three enemy units next to them and war declared; yours are selected as a group. `enemy` points the virtual cursor at theirs (`FOURX_CURSOR=duel`) for the combat card.
- `FOURX_MILITARY=1`: sends your soldiers to defend your first city and opens the Forces screen. Use with `FOURX_TURNS`.
- `FOURX_UNITS=1`: gives you every tech and 500 gold, puts one of each standard land unit around your warrior (selected, so its Upgrade button shows) and logs its world position.
- `FOURX_TRADE=1|incoming|counter`: at war with the first rival, opens the trade screen with them; `incoming` has them propose peace and gold to you; `counter` sets up a deal they'll answer with a counter-offer (click Propose Deal, e.g. `FOURX_CLICKS="1325,800,9;game"`).
- `FOURX_RAZE=1`: with `FOURX_TURNS`, puts a warrior next to a rival's city (not a capital if it has another), declares war and takes it, so the keep-or-raze prompt opens.
- `FOURX_GAMEOVER=win|lose`: opens the game-over screen as if you won by domination, or another civ won on score.
- `FOURX_MERCHANTS=1|move|go|idle`: meets every civ, reveals their cities and puts a Merchant in your first city; `1` opens the route picker, `move` the Move to City list, `go` sends it on the best route and selects it, `idle` stands it beside the city. Use with `FOURX_TURNS`.
- `FOURX_PASSAGES=1`: gives you every tech and digs a two-tile canal and the tunnel nearest your start (with a scout beside each) and builds the nearest bridge (with a scout on it and a galley moored beside it); logs their world positions.
- `FOURX_DIG=tile,...`: digs those tiles out into water once the world is shown, as a finished canal does (with `FOURX_LOAD`, to see a dig on a real save).
- `FOURX_POSTS=1`: with `FOURX_TURNS`, builds a fort and a watchtower on your first city's land; logs their world positions.
- `FOURX_PLACE=canal|tunnel|bridge|fort|watchtower`: gives you every tech, grows your cities' borders to their full reach and starts choosing a site for one in the city with the most (logs the sites' world positions). Use with `FOURX_TURNS`; `FOURX_CURSOR` on a site shows its ghost.
- `FOURX_WORKS=1`: gives you every tech, puts an improvement on each tile of your first city (and some roads, half of them railways; fish on a water tile if it has none, for Fishing Boats) and selects a Worker; logs the city's and the Fishing Boats' world positions. Use with `FOURX_TURNS` so a city exists (seed 11 has a coastal one).
- `FOURX_YIELDS=1|0` / `FOURX_STRATEGIC=1`: starts with the yields overlay (Y, normally on as set in Settings) on or off, or the strategic view (=) on.
- `FOURX_WEATHER=rain|snow[:depth]|storm|blizzard[:depth]|clear`: forces the weather around the camera (rain or snow with wet or snowed ground already there, `snow:0.3` for a light layer, a thunderstorm with lightning, a blizzard, or clear skies everywhere). `FOURX_WEATHER_SHIFT=x` centres the forced weather x units east of the camera, to see its edge.
- `FOURX_SEASON=0.0..1.0`: pins the time of year shown (northern midsummer 0.25, midwinter 0.75; normally it follows the turn). Visual only: sea ice follows the game's turn, so use `FOURX_TURNS` for that (turn 31 is late winter, 51 late summer).
- `FOURX_TIME=0.0..1.0`: pins the time of day (0 start of dawn, 0.33 noon, 0.62 dusk, 0.8 night).
- `FOURX_BIRDS=goose|starling|gull|1`: keeps a flock of birds (of that kind) passing over the camera's focus all the time, instead of one now and then.
- `FOURX_RAINBOW=1`: shows a rainbow straight away.
- `FOURX_AMBIENCE_LOG=1`: logs the ambient particles of each kind every few seconds.
- `FOURX_DEBUG=1`: shows the F3 overlay.
- `FOURX_GRID`: shows the hex grid.
- `FOURX_ICON_SHEET=icons.png`: writes every icon to one image.
- `XDG_CONFIG_HOME=<dir>`: where `open4x/settings.ron` is read from, so tests don't touch the real settings.
- `XDG_DATA_HOME=<dir>`: where saves go (`open4x/saves`), likewise.

## Architecture

Cargo workspace: `sim` (rules), `ai` (automation), `client` (Bevy app), `headless` (benchmark runner).

**`sim` is pure and deterministic.** It has no Bevy dependency and runs headless. Its state is `Game` (map, players, units, cities, territory). The state changes only through `Game::apply(player, Command) -> Result<Vec<Event>, CommandError>`. `Command::EndTurn` ends the turn for everyone and runs each city's turn, then research. Game logic is split across `impl Game` blocks:
- `city.rs`: growth, production, governor, borders (culture claims one tile at a time, `next_border_tile`, `expansion_threshold`). `Build::Project` (food, gold, science, culture) never finishes: it converts production in `city_output` every turn and only comes last in a queue. The human's governor builds no units and falls back on a project.
- `research.rs`: science, goals, per-tech progress, and a player's era (`Game::era`; eras are listed in `techs.ron`, and techs in era order). A tech needs its prerequisites and every tech of the previous era (`Rules::tech_needs`; `tech_requires` is only the named ones, as the tree draws them). Techs can carry `effects` like civ perks; `Game::civ_effects` includes those of known techs.
- `path.rs`: A* with movement points (`Path::left`: moves left on arrival). For the turns to many tiles at once, use one bounded search (`Game::reach_for`, `reachable_zoc`) rather than a `path_for` each: a failed search scans everything the unit can reach. Units count movement in tenths (`path::MOVE` to a point; `points`, `show_moves`): `UnitDef::moves`, terrain costs and perks are whole points, `Unit::moves`, `Mover::moves`, step costs and `turn_moves` are tenths. `Mover` (from `Game::mover`) says where a unit can go: land units embark onto water with the techs that `grant` it, ships (`domain: Sea`) sail and enter their own coastal cities.
- `combat.rs`: deterministic combat, one unit against one unit or a city. `combat_preview` is exactly what `Command::Attack` does. Cities defend themselves (`city_strength`: `city_own_strength` by era and size plus `garrison_strength`, half the strength of the land soldier standing in it, `Game::garrison`; walls add `city_walls` percent), every city fires at one enemy in range each turn (`city_range`, at least 1), and they repair less while `besieged`. The garrison takes no damage; ranged attacks bring the walls down but never take a city; a melee attack that brings it to 0 takes it, and at 0 a melee unit walks in (`CombatPreview::captures`); the garrison is pushed out (`flee`). On the turn it fell the captor may raze it instead (`Command::RazeCity`, `raze_problem`). Units with a Defend order that didn't move this turn count as fortified. Right-clicking an enemy unit out of reach gives a Hunt order (`Command::Hunt`, `Game::approach`, `pursue`): the unit closes in each turn and attacks when it can, until the target is gone or lost from sight. Attacks, zones of control and city fire only apply between players at war (`Game::at_war`, `Command::DeclareWar`); players meet (`Game::has_met`) when they first see each other.

- `diplomacy.rs`: deals (`Deal`, `Command::ProposeDeal`/`AcceptDeal`/`RefuseDeal`): peace and alliances, gold, gold per turn, open borders and cities; truces, payments, and closed borders (`Game::may_enter`, used by `Game::mover`). Declaring war moves each side's units out of the other's land. `Game::borders_in_the_way` says whose closed borders block a route.
- `purchase.rs`: spending gold (`Command::Buy`, `Command::BuyTile`): `buy_price`/`buy_problem` for units and buildings (the build in progress uses its stored production), `buyable_tiles`/`tile_price`/`tile_problem` for land, and unit upgrades (`upgrade_target`, `upgrade_price`, `upgrade_problem`, `Command::Upgrade`): units follow `upgrades_to` in `units.ron`, and a unit whose upgrade its owner can build is obsolete (left out of `available_builds`). Where a build can go is `Game::place_problem` (ships and `coastal` buildings need the coast, `requires` needs another building); buildings can need a strategic resource like units (`resource`, `has_resources_for`).
- `improvement.rs`: Workers' builds (`Command::Build`, `Work`, `Game::works` per tile), roads (a step between two road tiles costs 1; cities have roads), railways over roads (`Work::Railroad`, `has_rail`; a step costs `path::RAIL_COST`; cities get one when their owner learns the tech, `rail_stations`), `water` improvements (Fishing Boats, built embarked), clearing features (improvements with `features`, like the Lumber Mill, go only on those and keep them), Rome's road to the capital.
- `resource.rs`: resources on the map (`Tile::resource`, placed in mapgen, start balancing), who has them (`resource_counts`, `has_resources_for` for units that need one), luxury gold, resource deals.
- `climate.rs` and `Map::sea_ice`: seasons advance with turns (`TURNS_PER_YEAR`, `year_phase`, `season`, `swing` by latitude). Ice on water is worked out each turn from the tile's temperature then (no stored state): thin ice slows ships and embarked units, pack ice is impassable (`sea_ice` thresholds in `terrain.ron`; `Mover::season`).
- `trade.rs`: merchants and trade routes (`Command::Trade`, `Order::Trade(Route)` run in `run_trade` at turn end, `route_offers`/`route_offer`, `trip_gold`: gold, and food and production for the home city at home; ranked by `worth_per_turn`, `trade_capacity`, `Command::Transfer` to move one to another city). Merchants and units of players not at war pass each other (`Game::passes`, in `can_stop_at` and path blocking). Merchants' paths are cached in `Game::trade_paths` (not saved). Canals, tunnels and bridges (and the border posts, forts and watchtowers: `Passage::is_post`, built on the owner's land within `reach`; forts defend and fire in `combat.rs`, posts are pulled down by an enemy unit standing on them (`pull_down_posts`)) are city builds, `Build::Passage(Passage, tile)` (`improvement.rs`: `passage_problem`, `site_problem`, `passage_sites`, `canal_fits`/`bridge_fits`, `canal_shortcut`/`bridge_shortcut`); `Game::passages` lists the built tunnels and bridges and `Game::passage_tiles` gives one kind's, for `Mover` (`tunnels`, `bridges`). A finished canal turns its land into water for good (`Game::terraform`, `Event::TerrainChanged`), so there is no canal passage afterwards. A land unit on a bridge isn't at sea (`Game::at_sea`, `is_embarked`); ships sail under bridges as on any water.
- **Units and group orders**: one military unit per tile (`Game::slot`: civilians, land soldiers, ships and leaders each have a place, so a General shares a tile with a soldier), built in city queues like anything else. Many units are commanded together with group orders on each unit: `Order::Take { city }` (gather out of its fire, then strike together until it falls: ranged units at their full range, stepping in only when they can shoot, melee units on the ring in front of them) and `Order::Defend { city }` (a garrison inside, the rest on guard beside it), set with `Command::SetOrder` (`take_problem`, `defend_problem`) and carried out by `ai::orders`, the same for the player and the AI; units with such an order don't ask for orders (`units_needing_orders`) until it ends. Gold upkeep per unit is in `purchase.rs` (`unit_upkeep`, less `upkeep_allowance`; `process_upkeep` disbands a unit when broke).
- `experience.rs`: XP and ranks. Units earn XP in battle (`Unit::xp`, awarded in `attack` through `battle_xp`) and rise in rank on their own (`rank`, `rank_def`: a strength modifier in `side_mods`, extra healing). Generals (and Admirals, the General at sea: a sea unit with `Ability::General`, named from the civ's `generals`/`admirals` by `name_general`) lead their owner's units of the same domain within the `aura` range (`leader_of`: +`aura.strength` percent and the leader's traits, `leader_traits`), level up from those units' fights and choose traits (`Unit::traits`, `Command::ChooseTrait`; `auto_traits` at turn end takes the first missing one; a trait's `domain` limits it to Generals or Admirals): `aura_moves` (in `turn_moves` and `mover`), `unit_sight`, combat bonuses, healing, more XP. `ai::promote` chooses for computer players.
- Land belongs to players (`Game::territory`); `Game::district` is the city that works a tile (the owner's nearest within 3, derived by `refresh_districts`; use `set_territory` to change land).
- `victory.rs`: elimination, score and victory (domination by holding every original capital, or score at the turn limit). Checked after attacks and at turn end; `Game::victory` holds the first winner.

Map generation is in `mapgen.rs`, `tectonics.rs` and `climate.rs`; `shapes.rs` has the map types (`MapType`, `MapSettings::kind`), each a land mask added to the height before the sea level is cut (Fractal has none and is the `MapSettings` default, so tests keep their maps). `Map::start_land` limits where civs start (Terra's old world). Earth (`earth.rs`, `data/earth.ron`) is the real world sampled at any size, one fixed map whatever the seed (`mapgen::EARTH_SEED`; the setup screen hides the seed): columns run east from 180° W and rows span 90° N to 90° S, so `earth::lon_lat` / `tile_at` convert, and the climate model sees true latitudes. Its land is a half-degree grid of land shares and landmasses, run-length encoded (from public-domain Natural Earth data by `data/tools/earth_mask.py`, which rewrites those lists in place), with hand-placed straits and narrow seas, mountain ranges, great rivers and climate corrections (currents, monsoons). `mapgen::earth_layers` turns it into tiles: land above a share of the footprint, or most of its middle; peninsula tips and links within a landmass join; islands without a tile get their best one; straits are cut; and different landmasses never touch (the tile with less land goes, never a landmass's last). The generator skips its invented ranges, lakes and most rivers there. `Map::kind` remembers the type. `GameOptions::true_starts` puts each civ at its `home` (civs.ron) on Earth (`Game::home_start`: the homeland tile or a neighbour). The map is a hex grid with axial coordinates and wraps east–west (`hex::MapGrid`). Data is stored in flat arrays indexed by `TileId`.

**Rules are data.** `rules.rs` loads these files and validates them:
- `terrain.ron`, `units.ron`, `buildings.ron`, `techs.ron`, `civs.ron`, `improvements.ron`, `resources.ron`, `experience.ron` (ranks, the Generals' aura and traits, `Rules::experience`), and `earth.ron` (the Earth map, `Rules::earth`)

IDs are `u8` indices into those lists. Cross-references are resolved at load time, such as a tech's prerequisites or the `tech:` field on units and buildings. A tech's prerequisites must appear earlier in `techs.ron`, which rules out cycles and makes id order a valid research order. When adding content, the client also needs:
- an icon mapping in `client/src/icons.rs` (`Icon::unit`, `Icon::building`, `Icon::improvement`, `Icon::resource`; unique buildings map to the icon of what they replace)
- for improvements, a layout in `client/src/improvements.rs` (`tile_model`, keyed by `art`) placing props from `art/models/works.py`
- for units, a Blender script `art/models/<art>.py` (built .glb files are picked up automatically), or as a fallback `client/src/units.rs` (`unit_model`, keyed by `art`; ships in `ship_model`)
- for civs, an emblem drawing in `icons.rs` (`Icon::emblem`, keyed by `emblem`)

**Civilizations** (`civ.rs`, `data/civs.ron`): each player has a civ (`Player::civ`). A civ has colours, city names, a start bias, a homeland on Earth, AI drives and an agenda, and two perks. Perk `effects` are an `Effect` enum the sim applies where it matters: tile and city yields in `city.rs`, combat modifiers in `combat.rs` (`side_mods`), movement in `game.rs`, tech cost in `research.rs`. `planned` is text for parts that need systems that don't exist yet. Unique units and buildings live in `units.ron` / `buildings.ron` with `replaces`, and each is listed by exactly one civ. Use `Game::civ_unit` / `civ_building` to get a player's version of a standard id, and `Rules::building_is` to check "is a Market or replaces one". A new game takes a `GameSetup` (civs, human first, plus `GameOptions` such as the military unit limit). `Game::new(rules, map, ai_players)` is a shortcut for tests that uses the first civs.

**Automation:**
- The `ai` crate acts only through the same commands a player uses. `take_turn` drives computer players; `run_standing_orders` runs the human player's automated orders, such as Explore, and their Take and Defend orders (`orders.rs`, the same code the AI's units follow). `group.rs` turns a right-click with several units into orders (an enemy city: Take; ours: Defend; an enemy unit: Hunt; else they spread out around the tile).
- A computer player's turn: `strategy.rs` assesses power, threats and rivals and decides on war from the leader's drives and agenda (and `army`, the troops it favours, used by `production.rs`); then `research.rs`, `promote.rs` (Generals' traits), `production.rs` (sets city queues: units by the leader's mix up to the army it wants, a General for a big attack, an Admiral, ships, walls when threatened), `spend.rs` (upgrades units, buys units, buildings and tiles above a reserve), `military.rs` (gives land units orders: Defend for a garrison in every city and more where threatened or facing the enemy, Take on the war target for the rest at war, Generals with the attack), `navy.rs` (ships: Take on a coastal target on their sea, else Defend their nearest port; how many ships by `sea_stake`), `orders.rs` (carries the orders out), `fight.rs` (attacks worth making, for units without such an order), `work.rs` (automated Workers, also the human's Automate order) and `settle.rs`; `diplomacy.rs` (first) answers deals and proposes peace, alliances and open borders (when someone's land is in its way, see `Strategy::passage`), valuing everything on one scale. The AI keeps no state between turns: memory it needs (who attacked whom) is `Relation` in the sim, and units' Take orders keep its war target.
- City governors and auto-research live in `sim` and run only at turn end, and only if the player hasn't already chosen. This was an explicit design decision.
- Production is one shared pool per city that carries over when you switch builds. Research progress is kept per tech.

**`client` (Bevy 0.20):**
- `frontend.rs` is the front end: main menu → civ selection → game setup (`AppState::MainMenu` → `CivSelect` → `Setup`). Screens are rebuilt whenever the `NewGame` resource changes (or `TypePicker`, the map type picker over the setup screen, whose pictures `TypeThumbs` draws from fixed showcase seeds). Starting a game inserts a `WorldSpec` (rules, map settings, `GameSetup`). `map_preview.rs` paints a generated map as an image for the setup preview, off the main thread, with the tile under each pixel (`PreviewMap`), so players' shields can be dragged onto it to choose their starts (`NewGame::starts` → `GameSetup::starts`). `frontend::civ_badge` draws a civ's shield and emblem anywhere in the UI.
- `loading.rs` builds the world on a background task (`AppState::Loading` → `InGame`) from a `WorldSpec`, whose `WorldSource` is a new game or a saved one. Gameplay systems belong in `InGameSet`.
- `capture.rs`: the keep-or-raze prompt after we take a city.
- `diplomacy.rs`: the other civs under the top bar (met or "?", at war), each civ's panel (trade, declare war, truce and payments), and the confirmation before an attack that would declare war.
- `research_ui.rs`: the research tracker and the tech tree (columns by prerequisites, each era its own band of columns; it opens scrolled to the current research).
- City panel (`city_panel.rs`): the Defence section (strength, walls, fire, health, the garrison); a gold price next to every build buys it (`buy_button`); the "Buy tiles" toggle sets `land::BuyLand`, and `land.rs` puts clickable price tags and gold outlines on the tiles for sale.
- `trade.rs`: the trade screen, a negotiating table (four columns, live verdict from `ai::diplomacy::verdict`, the AI's counter-offers from `ai::diplomacy::answer`, Accept/Refuse/counter); deals proposed to you open it.
- Selecting and commanding many units (`play.rs`): `Selected` is the unit whose card shows, `Group` the units selected together (Ctrl-click adds or removes one, Shift-drag boxes them, a double-click takes every unit of that kind on screen; `box_select`); right-click goes through `play::order_units` (one unit attacks what it can reach now; otherwise `ai::group::command`). `forces.rs`: the group panel (instead of the unit card for a group: what's in it, health, orders, Fortify/Sleep/Skip/Stop), the Forces screen (O or the top bar's counter: every group by its order; clicking one selects it) and a unit's rank and a General's level and trait choice (`xp_stat`, `spawn_general`).
- `improvements.rs`: improvement and road models, resource badges, and the words for builds and resources. `yields.rs`: the yields overlay (Y). `strategic.rs`: the strategic view (=), on render layer 1; anything shown in both views needs `strategic::both_layers()`, and screen labels use `strategic::ground` for their height there. `icons::GlyphAtlas` has every icon and digit in one texture for map quads.
- `site_hints.rs`: city site markers while a Settler is selected (scored by `ai::settle::site_report`).
- `daylight.rs`: the real-time day/night cycle (`DayClock`). One directional light is the sun by day and the moon by night; light colour, ambient, clear colour and haze come from keyframes. Town windows use the shared `WindowGlow` material. The shaders' fog block reads the light from Bevy's `lights` view uniform (`fog_sky`), so clouds follow it; its `FOG_NOON_*` constants must match the noon keyframe (a test checks).
- `season.rs`: the shown season, easing after each turn (the season itself is `sim::climate`; 40 turns a year) and the one temperature model all snow follows: mean sea-level temperature, colder with height, plus a seasonal swing by latitude. The terrain bake writes mean and swing into the climate texture; the shaders' `climate_snow` (in the shared weather block) turns them into snow lying, for terrain and plants alike (plants carry their ground height in the vertex alpha). The top bar shows the time and season, the city panel the temperature. The plants' material (`vegetation::Scenery`) is shared by towns and improvements; the vertex alpha says what kind of surface it is (`snow_tag`: bare, evergreen, broadleaf with autumn colours and bare in winter, roofs and fields) and its ground height. `water.rs` redraws the sea ice (`IceCover`) each turn.
- `weather.rs`: weather by climate, visual only. A low-resolution RGBA texture over the fog's area (cloud cover with storms packed above 0.5, rain/snow falling, snow lying, wet ground) stepped on the CPU 4 times a second; the shaders' shared weather block (`weather_at`, test-checked like the fog block) darkens the ground where rain or snow falls (more under storms) and adds wet ground and settled snow; `shaders/precip.wesl` draws rain and snow as one mesh of quads wrapped around a box at the camera. `LocalWeather` (cover, storm, blizzard and lightning flash at the camera) dims the sun and flashes the sky in `daylight.rs` and closes in the haze in `settings.rs`; lightning bolts are one ribbon mesh rebuilt per strike.
- `ambience/`: life and atmosphere around the camera, visual only (setting "Wildlife and ambience"). `mod.rs` has `Stage` (the ground in view, time of day, weather) and `spot` (what's at a point: terrain, feature, temperature now, visible). `puffs.rs` is one particle mesh rebuilt each frame (`Puff`, `Shape`: smoke, leaf, glow, butterfly, drop, mist; `shaders/puffs.wesl` fades them at the ground and under fog of war). `towns.rs`: chimney smoke (spots from `cities::TownSpots`), wall torches, lamp posts on every road in a civ's land from the Classical era. `nature.rs`: dawn mist, autumn leaves, drifting snow, butterflies, fireflies, dust devils. `sea.rs`: leaping fish, whales, fishing boats. `roads.rs`: ox carts between a civ's towns. `herds.rs`: `Actor` (a rigged Blender model moved here and posed by `rigs::pose`) and the animals on resource and pasture tiles (`improvements::animal` spawns `HerdAnimal`s instead of static props). `rainbow.rs`. The game has no sound for now (the synthesised ambient sound was removed in October 2026 to be redone). The terrain shader adds heat shimmer over hot land at midday.
- `birds.rs`: flocks of birds that now and then cross the view (geese in a V, starlings, gulls near water), visual only: entities with flapping two-part wings, high above explored land, none at night, in storms or the strategic view.
- `merchants.rs`: the trade routes screen (`MerchantScreen`) and trade news. `placement.rs`: choosing a canal's, tunnel's or bridge's site (tint, ghosts via `improvements::ghost_model`, banner), and ghosts of passages in progress. `bridges.rs`: a bridge's deck (`Span`: which shores it joins, its height along the way, matching `art/models/bridges.py`) and `Bridges`, used by `units.rs` so land units walk on decks and ships moor alongside; the model is an era's arm and hub props (`improvements::bridge`, styled by the tile owner's era). `terraform.rs`: when a tile's terrain changes (`Event::TerrainChanged`, a dug canal), rebuilds the world around it from the map: heightfield, terrain chunks (`terrain::TerrainChunk`), terrain textures and mipmaps (`terrain::texture::rebake`, `image_util::update_mips`), water (`water::WaterGrid::extend`), ice and the rendering `GameMap`; anything reading heights after a change runs after `ReshapeSet`.
- `news.rs`: toasts and the notification log; post news with `Notice::news`/`alert` (`play.rs`). `minimap.rs`: the minimap.
- `gameover.rs`: the victory or defeat screen with every civ's score, opened by `Event::GameOver` or our own `Event::PlayerEliminated`.
- `saves.rs`: save files (`sim::save` writes a small readable header plus the gzipped game; saves from different rules are refused), autosave every n turns (a setting; the last 5 are kept), the save list used by the main menu and the pause menu, and **teardown**: leaving a game (loading another, or Exit to Main Menu) despawns every root entity with a `Node` or `Transform` that didn't exist before the first game, and resets per-game resources. A system that does something once per game should check `session.is_added()` rather than keep a `Local` flag.
- `play.rs` owns `Session { game, me }`. All input becomes `Session::command`, which publishes `GameEvent` messages. Renderers and panels run `.after(PlaySet)` and either react to those events or rebuild when `Session` changes. Most panels (city, unit, banners, tech tree) are despawned and rebuilt on change rather than updated in place.
- **Models made in Blender** (`art/`, Blender 5.2 in `~/.local/bin/blender`): every unit, ship, tree, town building, improvement and resource. Each `art/models/<name>.py` builds in metres facing -Y with `art/lib`: `kit.py` (materials with procedural patterns, metaball bodies `blobs` with `paint` for regions, `loft`, `sheet`, primitives, `Rig`, baking and export), `people.py` (one posable human body, outfits, helmets, shields, weapons), `beasts.py` (one parametric quadruped: horse, mule, ox, cow, sheep, deer, elephant, fox), `engines.py` (wheels, timbers), `ships.py` (hulls, oar banks, sails). Units (`kind="unit"`) bake a 512² colour texture with ambient occlusion, a metallic-roughness texture and the team mask (vertex colour red), and are skinned: bones (`Rig.bone`; `kit.bind` rigid, `kit.blend` weighted by distance) go out as `_JOINTS`/`_WEIGHTS` attributes and a `rig` string in the node's extras. Prop libraries (`kind="props"`: `trees`, `works`, `town`) are named nodes with colour and occlusion in vertex colours and a flag in alpha (`models::Flag`: foliage, team colour, window). `kit.preview` renders to `target/art/<name>.png` (with a side view); scripts named `_<name>.py` are studies, built only on request and exported to `target/art`, never into the game; `python3 art/tools/sheet.py out.png name...` puts previews side by side. The .glb files are committed (`crates/client/assets/models`, embedded by `build.rs`), so building the game doesn't need Blender.
- `models.rs` parses the .glb files (`gltf` crate, mipmaps added); `models::prop(name)` gives a library prop as a `procmesh::Model`. `units.rs` gives a unit with a rig a `SkinnedMesh` and joint entities (`dress`); `rigs.rs` animates them procedurally by joint name (people: `<p>hips`, `spine`, `arm_r_up`...; animals: `<p>body`, `fl_up`...; `wheel*`, `oar*`, `throw`, `barrel`, `hull`, `flag*`): walking in step with the distance covered, idle motion, and an attack by the rig's style (melee, thrust, bow, gun, siege, cannon), started from `Event::Combat`. Units without a Blender model fall back to `unit_model`. Towns (`cities.rs`) pick their buildings by the owner's era (`town_style`); windmill sails on farms spin (`improvements::Spinner`).
- The 3D scene uses a fixed isometric camera with custom WESL shaders in `src/shaders`, embedded with `embedded_asset!` from `main.rs`. Shaders use `ExtendedMaterial`, and an XRay material draws overlays visible through terrain.
- Two cameras: `camera::MainCamera` renders the scene (HDR, AgX); its child `IconCamera` (render layer `ICON_LAYER`, no tonemapping) blends map icons such as the yields over it and also draws the UI (`IsDefaultUiCamera`), so icons keep their true colours and stay under panels. Systems that need "the camera" must filter on `MainCamera`.
- East–west wrapping is handled by `wrap.rs` (`Wrapped`), using `nearest_shift` for screen-space positions.
- Fog of war is an R8 texture (`fog.rs`) sampled by every shader; it eases towards each new state (`FogFade`). The cloud code is copied into terrain, water and vegetation shaders and must stay identical (a test checks). Unexplored areas skip most rendering work: `Footprint` marks tree areas as `lod::Dormant` and stops unexplored terrain chunks from casting shadows.
- The UI kit is in `ui.rs`:
  - palette, fonts (Inter body, Cinzel headings, embedded)
  - `Tooltip` component, `icon_button`, `ButtonState` (active/disabled), `OwnStyle` to opt out of button styling
  - `pointer_over_ui`: map input must ignore the pointer when it's over UI
- Screen-anchored world labels (unit flags, city banners, resource badges, price tags, site markers) are children of the one `ui::WorldLabels` root (hundreds of separate UI roots are each laid out every frame), divide screen positions by `UiScale`, use `GlobalZIndex(-1)` so they stay below panels, and are moved with `ui::place_label`, which hides them off screen and writes `Node` only when they really moved (any `Node` write makes Bevy lay out the UI again).
- Icons are vector drawings rendered at startup with tiny-skia (`icons.rs`). Each icon also has a white variant for tinting.

## Conventions

- Keep `sim` free of rendering concerns. New rules go in `data/*.ron` plus `rules.rs` validation, with sim tests (see the `game_with_city` helper in `city.rs`).
- Visual changes are verified with `FOURX_SCREENSHOT` runs and by looking at the image. Use a scratch directory for screenshots and settings, not the repo.
- Bevy 0.20 gotchas:
  - Custom shaders must set `pbr_input.N` themselves; otherwise the normal prepass is wrong.
  - Bundles can't contain duplicate components; `ui::icon` already includes `Pickable::IGNORE`.
  - A system that tracks entities spawned in the same frame needs to check `Added<T>`.
  - `Activate` (button clicks) doesn't bubble: put the `observe(...)` on the entity with `Button`, not on a wrapper node.
